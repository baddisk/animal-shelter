# 📈 관리자 통계 기능 설치 · 사용 가이드

관리자 화면(`/admin.html`)에 **이용 통계 탭**과 이를 구동하는 **통계 집계 API**를 추가했습니다.
이미 수집 중이던 `/api/track` 이벤트를 관리자용 지표로 가공해 보여줍니다.

---

## 1. 무엇이 추가되었나

| 구분 | 파일 | 내용 |
|---|---|---|
| 서버 API | `server/server.js` | `GET /api/admin/stats`, `GET /api/admin/stats/export.csv` 추가 |
| 관리자 화면 | `admin.html` | 탭 UI(`개체·케어 기록` / `이용 통계`)와 통계 영역 추가 |
| 화면 로직 | `js/admin.js` | 통계 조회·렌더링(KPI·그래프·퍼널·TOP) 함수 추가 |
| 스타일 | `css/style.css` | 통계 전용 CSS(탭·카드·막대그래프·표) 추가 |

> 이벤트 수집(`POST /api/track`)과 프런트 전송(`js/app.js`의 `track()`)은 **기존 코드 그대로** 사용합니다.
> 새로 심을 추적 코드는 없습니다.

---

## 2. 설치 방법

### 2-1. 코드 반영

이 브랜치를 배포 대상에 병합하기만 하면 됩니다. **추가 npm 패키지가 없습니다.**

```bash
git fetch origin
git checkout arena/01a0ca91-animal-shelter
npm install      # 기존 의존성만 (신규 패키지 없음)
npm start
```

### 2-2. 환경변수

새로 필요한 환경변수는 **없습니다.** 기존 값을 그대로 씁니다.

| 변수 | 통계 기능에서의 역할 | 필수 |
|---|---|---|
| `ADMIN_PASSWORD` | 통계 API 인증(미설정 시 `shelter1234`). **운영에서는 반드시 변경** | 권장 |
| `MONGODB_URI` | 있으면 `events` 컬렉션에서 집계, 없으면 `data/events.json`에서 집계 | 선택 |
| `MONGODB_DB` | 이벤트 컬렉션이 있는 DB 이름(기본 `shelter`) | 선택 |

### 2-3. 저장소별 동작

* **MongoDB 모드** (`MONGODB_URI` 설정): `events` 컬렉션을 조회합니다. 재배포해도 데이터가 유지됩니다.
* **파일 모드** (미설정): `data/events.json`(최대 2만 건 롤링)을 읽습니다. 개발·소규모 운영용이며 **Render 등에서 재배포하면 초기화**됩니다.

> 💡 **운영 권장**: MongoDB 모드에서 조회 속도를 위해 인덱스를 한 번 만들어 주세요.
> ```js
> db.events.createIndex({ ts: -1 })
> ```

### 2-4. 확인

1. 서버 실행 후 `https://<도메인>/admin.html` 접속 → 로그인
2. 상단 **`📈 이용 통계`** 탭 클릭
3. 기간 버튼(오늘 / 7일 / 30일 / 90일)으로 조회

## 3. API 명세

두 엔드포인트 모두 **관리자 토큰 필수**입니다 (`POST /api/admin/login`으로 발급).
미인증 요청은 `401`을 반환합니다.

### `GET /api/admin/stats`

| 쿼리 | 설명 | 기본값 |
|---|---|---|
| `days` | 집계 기간(1~365일, KST 기준) | `7` |
| `refresh` | `1`이면 1분 캐시 무시 | – |

```bash
TOKEN=$(curl -s -X POST http://localhost:3000/api/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"password":"shelter1234"}' | jq -r .token)

curl -s "http://localhost:3000/api/admin/stats?days=30" \
  -H "Authorization: Bearer $TOKEN" | jq
```

**응답 구조**

### `GET /api/admin/stats/export.csv`

일별 집계를 CSV로 내려받습니다. 엑셀에서 한글이 깨지지 않도록 **UTF-8 BOM**을 붙입니다.

```

```

## 4. 화면 구성

관리자 화면 상단에 탭이 생깁니다. 기존 케어 기록 화면은 **그대로 첫 번째 탭**에 있습니다.

* **KPI 카드 6종** — 상세 열람 / 링크 유입 / 입양 문의 / 공유·복사 / 평균 체류 / 페이지 조회
* **일별 추이 막대그래프** — 열람·문의·공유 3계열. 외부 차트 라이브러리 없이 CSS만 사용(내부망·오프라인에서도 동작)
* **전환 퍼널** — 상세 열람 → 사진 탐색 → 입양 문의 전환율
* **유입 경로** — 공유 링크 vs 목록 탐색 비율
* **관심 많은 개체 TOP** — 행을 클릭하면 해당 개체의 케어 기록 화면으로 바로 이동
* **노출이 적은 개체** — 열람 0회는 빨간 뱃지로 표시해 홍보 대상을 짚어줍니다
* **많이 쓰인 필터** — 방문자가 어떤 조건으로 찾는지

## 5. 설계상 참고사항

* **KST 기준 집계** — 보호소 업무 기준인 한국 시간(UTC+9)으로 하루를 끊습니다.
* **1분 서버 캐시** — 새로고침을 연타해도 재집계가 반복되지 않습니다. `refresh=1`로 우회 가능합니다.
* **이상치 제거** — 체류 시간은 1초 미만·1시간 초과 값을 평균에서 제외합니다(탭을 켜둔 채 방치한 경우).
* **공유는 퍼널에서 분리** — 한 번 열람에 공유·복사가 여러 번 일어날 수 있어 전환율이 100%를 넘습니다. 별도 보조 지표(`shareMetric`)로 제공합니다.
* **개인정보 미수집** — 방문자 식별자·IP·UA를 저장하지 않습니다. 집계 수치만 오갑니다.
* **외부 API 실패 내성** — 공공데이터 API가 죽어도 개체 이름만 비고 통계 수치는 정상 출력됩니다.
* **검색 차단 유지** — `robots.txt`가 이미 `/admin.html`을 차단하고 있어 통계 화면도 노출되지 않습니다.

## 6. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 통계가 전부 0 | 아직 방문 이벤트가 없습니다. 사이트에서 개체 상세를 몇 번 열어본 뒤 새로고침하세요. |
| 재배포 후 통계 초기화 | 파일 모드입니다. `MONGODB_URI`를 설정해 영구 저장으로 전환하세요. |
| `401 관리자 인증이 필요합니다` | 토큰 만료(서버 재시작 시 세션 초기화). 다시 로그인하세요. |
| 개체 이름이 안 뜨고 번호만 표시 | 공고가 종료되어 공공 API 목록에서 빠진 개체입니다. 수치는 정상입니다. |
| 90일 조회가 느림 | MongoDB에 `{ ts: -1 }` 인덱스를 생성하세요. |
